## Phase 1: Route Split — Implementation Plan

### Context

The `src/server/routes/projects.ts` file is 1,298 lines containing route handlers for snapshots, dimensions, members, relationships, hierarchy, varying properties, baselines, diff runs, bulk updates, change sets, validation config, and issues — all mixed together. The goal is to extract these into 7 domain-specific sub-routers, create shared helpers, and leave `projects.ts` at ~100 lines (project CRUD + sub-router mounts).

Key findings:
- `runProjectValidation` is exported and imported by `src/server/ai/projectContext.ts` — it needs to move to a shared helper
- No `src/server/helpers/` directory exists yet — will be created
- `app.ts` mounts the project router at `/api/projects` (line 131) — sub-routers use `mergeParams: true` so URLs stay the same
- Tests exercise routes via HTTP (start app on port 0, fetch). Route paths are unchanged so tests pass without modification.
