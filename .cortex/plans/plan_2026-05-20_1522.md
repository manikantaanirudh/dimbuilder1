## Autoresearch-Style Autonomous Improvement Loop for Dim Builder

### Context

Your 567MB real metadata XML (`metadata/Dev_Metadata_20260516_202239Z.xml`) contains dozens of OneStream properties that aren't in your property dictionary, generating `XML_UNKNOWN_*` validation warnings. The autoresearch pattern (modify → measure → keep/revert) maps perfectly to this: the agent modifies the property dictionary, measures how many unknown warnings remain, and keeps improvements.

### What We'll Build

An **autonomous improvement loop** with 3 campaigns the agent can run:

| Campaign | File Modified | Metric (lower = better) |
|----------|--------------|------------------------|
| `dictionary` | `oneStreamPropertyDictionary.ts` | Count of `XML_UNKNOWN_*` issues after import+validate |
| `enums` | `oneStreamPropertyDictionary.ts` | Count of `INVALID_ENUM_VALUE` issues |
| `performance` | `validationEngine.ts` | Time (ms) to validate all dimensions |

### Architecture (3 files, matching autoresearch pattern)

```
scripts/
  autoresearch/
    program.md          ← Instructions for the AI agent (like Karpathy's)
    benchmark.ts        ← Fixed harness: imports XML, runs validation, outputs metrics (like prepare.py)
    results.tsv         ← Experiment log (gitignored)
```

**`benchmark.ts`** (the fixed measurement harness):
1. Imports the real 567MB metadata XML using `parseOneStreamXml()`
2. Stores dimensions in-memory (no DB needed)
3. Runs `validateDimension()` on each dimension
4. Outputs structured metrics:
   ```
   ---
   xml_unknown_count:     47
   invalid_enum_count:    12
   total_issues:          89
   import_time_ms:        3200
   validate_time_ms:      450
   dimensions_count:      15
   members_count:         2340
   tests_pass:            true
   ---
   ```
5. Also runs `npx vitest run` and reports pass/fail (safety gate - never merge changes that break tests)

**`program.md`** (adapted for your project):
- Instructs the agent to work on `src/shared/oneStreamPropertyDictionary.ts`
- Goal: reduce `xml_unknown_count` to 0
- Each iteration: modify dictionary → run benchmark → keep if metric improves + tests pass
- Simplicity criterion: prefer minimal definitions over complex ones
- Safety: never break existing tests, never remove existing definitions

### Implementation Steps

1. **Create `scripts/autoresearch/` directory**

2. **Create `scripts/autoresearch/benchmark.ts`** (~80 lines):
   - Import `parseOneStreamXml` from shared
   - Import `validateDimension` from shared
   - Read the metadata XML file
   - Parse it, run validation with default config
   - Count issues by code (XML_UNKNOWN_*, INVALID_ENUM_VALUE, etc.)
   - Time the import and validation phases
   - Run `npx vitest run` as a subprocess, capture pass/fail
   - Print structured output block

3. **Create `scripts/autoresearch/program.md`** (~100 lines):
   - Adapted from Karpathy's format for this project
   - Campaign: "Property Dictionary Expansion"
   - Defines what the agent can/cannot modify
   - Defines the loop (modify → commit → benchmark → keep/revert)
   - Explains the metric and how to interpret results

4. **Add a convenience npm script** in `package.json`:
   ```json
   "benchmark": "tsx scripts/autoresearch/benchmark.ts"
   ```

5. **Add `scripts/autoresearch/results.tsv` to `.gitignore`**

### How to Use It

Once set up, you point an AI coding agent (Claude Code, Codex, etc.) at the repo and give it the `program.md` as instructions. The agent will:

1. Run `npm run benchmark` to establish baseline
2. Study the XML to find unmapped properties
3. Add `define(...)` entries to the property dictionary
4. Run benchmark again — if `xml_unknown_count` drops and tests pass, keep
5. Repeat indefinitely (each iteration ~2-3 min on your machine)

You can leave it running overnight and review the results in the morning via `results.tsv` and `git log`.

### Verification
