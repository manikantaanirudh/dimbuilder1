# Plan: Fix XML Fidelity to Match Real OneStream Metadata XML Format

## Context

After comparing the app's XML export against a real 567MB OneStream 9.2.0 metadata extract (`metadata/Dev_Metadata_20260516_202239Z.xml`), I identified **6 critical fidelity gaps** that would cause the app's exported XML to be structurally different from what OneStream produces/expects.

### Key Findings from Real OneStream XML

**Real format patterns:**
```xml
<!-- Non-varying property -->
<property name="AccountType" value="Revenue" />

<!-- Varying-capable with empty context (default value) -->
<property name="Formula" scenarioType="" time="" revertToDefaultScenarioType="false" value="..." />
<property name="InUse" scenarioType="" time="" revertToDefaultScenarioType="false" value="True" />

<!-- Cube-varying property -->
<property name="FlowConstraint" cubeType="" value="root" />

<!-- Scenario-only varying (no time attr) -->
<property name="WorkflowChannel" scenarioType="" value="NoDataLock" />

<!-- Entity relationship with child properties -->
<relationship parent="root" child="EntityName">
    <properties>
        <property name="ParentSortOrder" value="0" />
        <property name="PercentConsolidation" scenarioType="" time="" revertToDefaultScenarioType="false" value="100.00" />
        <property name="PercentOwnership" scenarioType="" time="" revertToDefaultScenarioType="false" value="100.00" />
        <property name="OwnershipType" scenarioType="" time="" revertToDefaultScenarioType="false" value="FullConsolidation" />
        <property name="Text1" scenarioType="" time="" revertToDefaultScenarioType="false" value="" />
    </properties>
</relationship>

<!-- Non-Entity relationship (inline aggregationWeight) -->
<relationship parent="Drivers" child="DriverMethod" aggregationWeight="1.0" />

<!-- Empty members/relationships -->
<members />
<relationships />
```

## Identified Fidelity Gaps

### Gap 1: Varying property context attributes always emitted (even when empty)
**Real:** Properties that support varying ALWAYS emit `scenarioType=""`, `time=""`, `revertToDefaultScenarioType="false"` even for default values.
**App:** Only emits these when truthy (`if (value.cubeType)`, `if (value.scenarioType)`, `if (value.timeMember)`).
**Fix:** For varying-capable properties, always emit context attributes with empty string defaults.

### Gap 2: `revertToDefaultScenarioType` attribute missing entirely
**Real:** `revertToDefaultScenarioType="false"` is present on scenario/time-varying properties.
**App:** Has no concept of this attribute. Not in `VaryingPropertyValueRecord`, not emitted.
**Fix:** Add `revertToDefaultScenarioType` to the varying property model and always emit it on varying properties.

### Gap 3: `time` vs `timeMember` attribute naming
**Real XML:** Uses `time=""` as the attribute name.
**App:** Uses `timeMember` as the attribute name in export.
**Fix:** Change export to emit `time` instead of `timeMember`. Keep `timeMember` as internal field name.

### Gap 4: Empty-value properties are stripped
**Real:** OneStream emits ALL properties for each member, even with `value=""` (e.g., `Text1` through `Text8`, Formula, etc.).
**App:** Filters out empty values (line 393: `.filter(([, value]) => value && ...)`).
**Fix:** Add an option to emit all schema-defined properties even when empty, matching OneStream's completeness. Default behavior preserves backward compat (sparse export), but add a `fullPropertyEmission: true` mode that emits all defined properties.

### Gap 5: Self-closing empty elements
**Real:** Uses `<members />` and `<relationships />` when empty.
**App:** Always emits `<members>...</members>` wrapping tags.
**Fix:** Emit self-closing tags when no members/relationships exist for a dimension.

### Gap 6: Non-varying properties that OneStream renders with varying context
**Real:** Properties like `InUse`, `Formula`, `FormulaForCalcDrillDown`, `Text1`, `WorkflowChannel`, `AllowAdjustments`, `SiblingConsolidationPass` are ALWAYS emitted with varying context attributes.
**App:** Renders these as simple `<property name="..." value="..." />` without context attributes when they're stored in the main properties record (not in `VaryingPropertyValueRecord`).
**Fix:** The property dictionary must declare which properties require varying-context attributes even for their "default" value. During export, if a property `supportsVarying: true`, emit it with the appropriate empty context attributes.

## Implementation Steps

### Step 1: Update `VaryingPropertyValueRecord` and types
- Add `revertToDefaultScenarioType: boolean` field (default `false`)
- Keep `timeMember` as the internal field name but map to `time` in XML output

### Step 2: Enhance the OneStream Property Dictionary
- Add a `varyingContextType` field to property definitions: `"scenarioTime"` | `"scenario"` | `"cubeType"` | `"none"`
- Mark all properties observed in real XML with appropriate varying context type:
  - `scenarioTime`: Formula, FormulaForCalcDrillDown, InUse, Text1-8, AllowAdjustments, AllowAdjustmentsFromChildren, PercentConsolidation, PercentOwnership, OwnershipType
  - `scenario`: WorkflowChannel, SiblingConsolidationPass, SiblingRepeatCalcPass, AutoTranslationCurrencies
  - `cubeType`: FlowConstraint, ICConstraint, UD1-8Constraint, UD1-8Default, ICMemberFilter
  - `none`: AccountType, FormulaType, AllowInput, IsConsolidated, etc.

### Step 3: Update `renderPropertyLines()` in `xmlExport.ts`
- When a property definition has `varyingContextType !== "none"`, emit the appropriate context attributes:
  - `scenarioTime` → `scenarioType="" time="" revertToDefaultScenarioType="false"`
  - `scenario` → `scenarioType=""`
  - `cubeType` → `cubeType=""`
- Change attribute rendering to emit `time` (not `timeMember`) for varying properties

### Step 4: Update `renderVaryingPropertyLines()` in `xmlExport.ts`
- Always emit context attributes (even when empty string), not just when truthy
- Add `revertToDefaultScenarioType` attribute
- Use `time` instead of `timeMember` as the XML attribute name

### Step 5: Add `fullPropertyEmission` export option
- New option: `emitAllSchemaProperties?: boolean` (default `false`)
- When true, emit all schema-defined fields for each member/relationship, using `value=""` for missing ones
- This matches OneStream's full extraction format

### Step 6: Fix empty element rendering
- When a dimension has 0 members: emit `<members />`
- When a dimension has 0 relationships: emit `<relationships />`

### Step 7: Update XML import to properly handle varying context attributes
- When parsing `<property>` elements, detect `scenarioType`, `time`, `revertToDefaultScenarioType`, `cubeType` attributes
- If these context attributes are present (even empty), store the property with its varying context rather than treating it as a simple property
- Map `time` XML attribute → `timeMember` internal field

### Step 8: Update tests
- Add round-trip test using a realistic XML sample with varying properties
- Update existing XML export tests for new attribute format
- Add test for `fullPropertyEmission` mode
- Add test for empty member/relationship self-closing

### Step 9: Update documentation
- `docs/xml-generation-guide.md` - Document the varying property rendering rules
- `docs/export-modes.md` - Document `fullPropertyEmission` option
