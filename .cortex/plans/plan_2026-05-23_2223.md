## Context

**Explored:** schema.ts, database.ts, repositories.ts, app.ts, environments route/test, onestream connector pattern, client API, authorization middleware, shared types.

**Key Patterns Identified:**
- Schema: Single `schemaSql` string in `src/server/db/schema.ts` with all CREATE TABLE/INDEX statements
- Database: `createDatabase()` in `database.ts` runs schema then `evolveSchema()` for migrations
- Repositories: Single `createRepositories(db)` function in `repositories.ts` returning a huge object literal with all domain repos; exported `Repositories` type via `ReturnType<typeof createRepositories>`; snake_case DB columns mapped to camelCase via `mapXxx()` functions; uses `nanoid()` for IDs, `now()` for timestamps
- Routes: `createXxxRouter(repos, config)` pattern, returns Express `Router`, uses `zod` validation, wired in `app.ts` with optional `requireRole()` middleware
- Tests: Vitest, in-memory DB via `createDatabase(":memory:")`, spin up real HTTP server on port 0, register admin user via `/api/auth/register` + login, then test via `fetch()`
- Client API: `apiGet/apiPost/apiPatch/apiDelete` helpers in `src/client/api/client.ts`
- Connectors: Interface-based (`OneStreamApiClient`), factory pattern with mock + real implementations
