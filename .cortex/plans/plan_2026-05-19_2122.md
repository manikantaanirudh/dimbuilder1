## Enhancement Implementation Plan

### Context

This is a full-stack React+Express+SQLite application ("SR Onestream Dim Builder") for managing OneStream XF dimension metadata. The 6 requested enhancements span server routes, client components, config, and existing validation/export logic.

**Key findings:**
- No project rename/update API exists yet (only create/delete)
- Export already supports per-dimension via `?dimensionId=` query param but the guard runs at project level
- Grid filtering is currently a simple text search on loaded records
- No admin page exists; config is YAML-only
- "Save As" would be a named snapshot (the existing Save creates an auto-named snapshot)
- Test infra: Vitest with 27 test files, integration tests spin up in-memory SQLite

---

### Implementation Steps

#### 1. Project Rename
**Files:** `repositories.ts`, `projects.ts` (route), `client.ts` (API), `AppShell.tsx` or `Dashboard.tsx`

- Add `repos.projects.update(projectId, { name })` method in repositories
- Add `PATCH /api/projects/:projectId` route accepting `{ name, description }`
- Add `renameProject(projectId, body)` in client API
- Add inline-editable project name on Dashboard (click to edit the `<h1>`)
- Immediately rename to "Spaulding Ridge Onestream Dim Builder" via config change in `dimbuilder.yaml` (productName/title)

#### 2. Per-Dimension XML Export (bypass project-level blocking)
**Files:** `exportGuards.ts`, `export.ts` (route), `viewModel.ts`, `ExportModal` or `DimensionWorkspace.tsx`

- Add a new export guard variant: `assertDimensionCanExport()` that checks only the specified dimension's issues (not the whole project)
- Modify the XML route: when `?dimensionId=` is provided, use per-dimension guard instead of project-level guard
- Add a "Download XML" button per dimension on the `DimensionWorkspace` toolbar (next to the status badge) that is enabled when that specific dimension has no blocking issues
- Update `getExportAvailability()` to accept optional `dimensionId` for dimension-scoped availability

#### 3. Admin/Validation Rules Page
**Files:** New `AdminPanel.tsx` component, `AppShell.tsx` (navigation), config route

- Create `AdminPanel.tsx` component showing all validation rules from the config:
  - Table with columns: Rule Code, Description, Current Severity, Blocks Export (yes/no)
  - Group by category (Member, Relationship, Hierarchy, OneStream Profile, XML Preservation)
  - Read-only display (config is YAML-driven) with clear indication of which rules are "critical" (those whose severity is in `exportBlockedBySeverities`)
- Add "Admin" link in sidebar or toolbar (new nav item)
- Source data from `GET /api/config` (already exists) plus a new `GET /api/config/validation-rules` endpoint that returns structured rule metadata

#### 4. Rename Project to "Spaulding Ridge Onestream Dim Builder"
**Files:** `config/dimbuilder.yaml`

- Update `application.productName` and `application.title` to "Spaulding Ridge Onestream Dim Builder"

#### 5. Save As (Named Snapshot)
**Files:** `AppShell.tsx`, `ImportExportModals.tsx` or new small modal, `client.ts`

- Add "Save As" button in toolbar (or dropdown next to Save)
- Show a small modal/prompt asking for snapshot name and optional description
- Call existing `createProjectSnapshot(projectId, { name, description })` endpoint (already supports named snapshots)
- The existing Save auto-names; Save As lets the user pick the name

#### 6. Issue-Filtered Grid Navigation (Click Error/Warning Counts)
**Files:** `DimensionWorkspace.tsx`, `EditableGrid.tsx`, `viewModel.ts`

- Make the error/warning counts in the FactStrip clickable (wrap in `<button>`)
- Add `issueFilter` state to `DimensionWorkspace`: `"all" | "errors" | "warnings"`
- Pass filter to `EditableGrid` as a new prop
- In `EditableGrid`, when filter is active:
  - Collect entity IDs with matching-severity issues from the issues list
  - Filter `records` to only those whose ID is in the set
  - Show an "All" button in the grid toolbar to clear the filter
- The "All" button resets `issueFilter` to `"all"`
