## Context

I explored the full application architecture. Key findings:

- **Validation issue click → row navigation**: `IssueCard` is purely presentational (no `onClick`). The `EditableGrid` has no `scrollToIndex` or `highlightedRow` mechanism. Issues reference rows via `entityId` (UUID of member/relationship) and `entityType`.
- **Table alignment**: The grid uses CSS Grid with `repeat(N, minmax(160px, 1fr))` for all columns uniformly. Header and row share the same formula but are disconnected (header is sticky, rows are absolutely positioned within the virtualizer).
- **Project management**: No "Open Project" UI exists. No "Clear Session" / "Close Project" functionality. The `CreateProjectModal` already accepts a name. The `repos.projects.delete()` exists in the DB layer but is not exposed via any HTTP route. `store.projects` is loaded but unused in the UI.
