## Production Readiness Implementation Plan

### Context

Explored the existing architecture: Express app in `src/server/app.ts`, YAML config in `config/dimbuilder.yaml`, TypeScript types in `src/shared/appConfigTypes.ts`, SQLite schema with existing `users` table (no password column), tests use `createApp()` directly. All 10 recommendations will be implemented in priority order.

### Implementation Steps

#### Step 1: Basic Auth Middleware
- Add `auth` section to `config/dimbuilder.yaml`:
  ```yaml
  auth:
    enabled: true
    username: admin
    password: changeme  # or use env var AUTH_PASSWORD
  ```
- Add `AuthConfig` interface to `appConfigTypes.ts`
- Create `src/server/middleware/basicAuth.ts` — checks `Authorization: Basic ...` header against config credentials, returns 401 with `WWW-Authenticate: Basic` header on failure
- Apply middleware in `app.ts` before all `/api/*` routes (except `/api/health`)
- Update tests to include `Authorization` header when auth is enabled, or pass `auth: { enabled: false }` config in test fixtures

#### Step 2: GitHub Actions CI Pipeline
- Create `.github/workflows/ci.yml`:
  - Trigger on push/PR to main
  - Steps: checkout, setup Node 22, `npm ci`, `npm test`, `npm run build`

#### Step 3: Graceful Shutdown
- Update `src/server/index.ts`:
  - Store server reference from `.listen()`
  - Handle `SIGTERM` and `SIGINT` signals
  - Call `server.close()`, then `db.close()`, then `process.exit(0)`
  - Add 10-second force-exit timeout

#### Step 4: Structured Logging (pino)
- Install `pino` dependency
- Create `src/server/logger.ts` exporting a pino instance
- Replace `console.log` / `console.error` with logger calls
- Add request logging middleware (`pino-http` or manual) that logs method, path, status, duration
- Wire into the global error handler

#### Step 5: Test Coverage Configuration
- Install `@vitest/coverage-v8` as devDependency
- Update `vitest.config.ts` with coverage settings:
  ```ts
  coverage: {
    provider: 'v8',
    include: ['src/shared/**', 'src/server/**'],
    thresholds: { lines: 70, branches: 60 }
  }
  ```
- Add `"coverage": "vitest run --coverage"` npm script

#### Step 6: Linter (ESLint)
- Install `eslint`, `@eslint/js`, `typescript-eslint` as devDependencies
- Create `eslint.config.mjs` with TypeScript support, recommended rules
- Add `"lint": "eslint src/"` npm script
- Fix any immediate lint errors that block the build

#### Step 7: CORS Restriction
- Update CORS config in `app.ts` to use origin whitelist from config:
  ```yaml
  server:
    corsOrigins: ["http://127.0.0.1:5173"]  # dev client
  ```
- In production mode, only allow configured origins

#### Step 8: Input Validation with Zod
- Zod is already a dependency — start using it
- Create `src/server/middleware/validate.ts` with a `validateBody(schema)` middleware factory
- Add Zod schemas for the most critical routes: project create/update, member create, relationship create, config update
- Apply to routes in `projects.ts`, `config.ts`

#### Step 9: Dockerfile
- Create `Dockerfile` (Node 22 Alpine, multi-stage build):
  - Stage 1: install deps + build
  - Stage 2: production image with only dist + node_modules
- Create `.dockerignore` (node_modules, data/, metadata/, .git)
- Add `"docker:build"` and `"docker:run"` npm scripts (documentation only)

#### Step 10: Rate Limiting
- Install `express-rate-limit`
- Add rate limiter middleware in `app.ts`:
  - General: 100 req/min per IP
  - Import/Export: 10 req/min per IP (heavier operations)

### Verification

After each step:
- `npm test` — all 210+ tests pass
- `npm run build` — TypeScript compiles cleanly
- Manual: start server with `npm run dev`, confirm API works with/without auth header

Final verification:
- `npm run lint` — no errors
- `npm run coverage` — meets 70% threshold
- `docker build .` — image builds successfully
- Confirm CI workflow YAML is valid syntax
