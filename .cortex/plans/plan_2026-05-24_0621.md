## Implementation Plan: Impact Analysis Engine

### Context
Explored the project structure thoroughly. Key findings:
- **Schema**: All tables in `src/server/db/schema.ts` as a single SQL template literal with CREATE TABLE + indexes
- **Repositories**: Single `createRepositories()` function returning a nested object; `Repositories` type is inferred via `ReturnType`. Uses `nanoid()` for IDs, `now()` for timestamps, `parseJson()` for JSON fields
- **Routes**: Express Router pattern with Zod validation, `repos` and `config` injected. Returns `Router`
- **Client API**: `src/client/api/client.ts` exports typed functions using `apiGet`/`apiPost` helpers
- **Tests**: Vitest with `describe/it/expect`, test fixtures in `src/test/fixtures.ts`, uses in-memory DB + HTTP server for API tests, pure-function tests for shared logic
- **Hierarchy**: `src/shared/hierarchyAnalytics.ts` has `buildHierarchyPaths`, `findOrphanMembers`, `classifyMembersAsLeafOrParent` — exactly what we need for impact analysis

### Implementation Steps

**Step 1: Create `src/shared/impactTypes.ts`**
- Define all types as specified: `ImpactAnalysisType`, `ImpactSeverity`, `ImpactScope`, `HierarchyImpact`, `CrossDimensionImpact`, `DataImpact`, `SecurityImpact`, `ImpactReport`, `ImpactAnalysisRecord`, `ImpactAnalysisRequest`

**Step 2: Add `impact_analyses` table to `src/server/db/schema.ts`**
- Append CREATE TABLE + CREATE INDEX before the closing backtick, after the member_source_registry indexes

**Step 3: Create `src/server/impact/impactEngine.ts`**
- Core engine with functions:
  - `analyzeHierarchyImpact(scope, dimension, members, relationships)` — uses `buildHierarchyPaths` and `findOrphanMembers` from hierarchyAnalytics to detect orphans, path changes, depth changes
  - `analyzeCrossDimensionImpact(scope, allDimensions, allMembers, allRelationships)` — searches property values and relationship properties in other dimensions for references to target members
  - `analyzeDataImpact(scope, members, classifications)` — heuristic: leaf members more likely to have data
  - `analyzeSecurityImpact(scope, dimension, relationships, targetParent)` — compare accessGroup of current parent vs new parent using dimension metadata
  - `calculateSeverity(report)` — HIGH/MEDIUM/LOW/NONE based on findings
  - `generateRecommendations(report)` — contextual suggestions
  - `runImpactAnalysis(request, projectData)` — orchestrator that calls all analyzers and returns `ImpactReport`

**Step 4: Add `impactAnalyses` repository section to `src/server/db/repositories.ts`**
- `create(input)` — INSERT with nanoid, returns `ImpactAnalysisRecord`
- `listByProject(projectId)` — SELECT ordered by created_at DESC
- `findById(id)` — SELECT single record
- Add before the closing `};` of `createRepositories`, after `memberSourceRegistry`

**Step 5: Create `src/server/routes/impact.ts`**
- `createImpactRouter(repos, config)` returning Router
- `POST /api/projects/:projectId/impact-analysis` — validate with Zod, load project data, run engine, persist, return report
- `GET /api/projects/:projectId/impact-analyses` — list past analyses
- `GET /api/impact-analyses/:id` — get specific analysis
- `POST /api/projects/:projectId/what-if` — same as impact-analysis with `type: "whatIf"`

**Step 6: Wire into `src/server/app.ts`**
- Import `createImpactRouter`
- Add `app.use("/api", createImpactRouter(repos, config))` after existing route registrations

**Step 7: Add client API functions to `src/client/api/client.ts`**
- `runImpactAnalysis(projectId, request)` — POST
- `fetchImpactAnalyses(projectId)` — GET
- `fetchImpactAnalysis(id)` — GET
- `runWhatIfAnalysis(projectId, request)` — POST

**Step 8: Create `src/client/components/ImpactAnalysisPanel.tsx`**
- Simple panel component following `EnvironmentPanel` pattern
- Shows form to select members + action, run analysis, display severity badge + results

**Step 9: Create `src/test/impactAnalysis.test.ts`**
- Pure-function tests for the engine (no HTTP server needed):
  - Delete leaf → low severity, no orphans
  - Delete parent with children → high severity, orphans detected
  - Move member → consolidation paths changed
  - Cross-dimension reference detection
  - Security impact (different access groups)
  - Recommendation generation
  - Severity calculation
- API integration tests (HTTP server + in-memory DB):
  - POST/GET endpoints return correct data
  - 404 for missing project
  - Persisted analyses are retrievable
