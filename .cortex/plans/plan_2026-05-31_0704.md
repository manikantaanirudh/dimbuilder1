## Goal
Apply Karpathy's "Tip 1: full context" to the in-app Project Assistant. Today the NL engine (`queryParser.ts`) only does member lookups; questions like "summarize my project", "what's blocking export", "is my project healthy" fall through to a weak keyword search. I'll inject **project-level context** (counts, validation summary, export-readiness, top issues) and add intents that answer those questions.

## Context (findings)
- `ChatPanel.tsx` POSTs `{ question }` to `/api/projects/:id/ai/query`; the server already loads dimensions/members/relationships and calls `runNaturalLanguageQuery` (deterministic, not an LLM).
- Reusable, no new computation needed: `runProjectValidation(repos, config, projectId)` (projects.ts:909, module-scoped) + `summarizeValidationIssues(issues, blockingSeverities)` → `ValidationSummary { totalIssues, blockingIssues, errors, warnings, infos }`.
- Change is backwards-compatible: context is an optional param, so existing 535+ tests and behavior are preserved.

## Implementation steps
1. **`src/server/routes/projects.ts`** — add `export` to the existing `runProjectValidation` function (no logic change) so it can be reused.
2. **New `src/server/ai/projectContext.ts`** — `buildProjectAIContext(repos, config, projectId): ProjectAIContext | null` returning project name, dimension/member/relationship counts, per-dimension breakdown, the `ValidationSummary`, `exportReady` (= blockingIssues === 0), and top issue codes (grouped from `runProjectValidation`).
3. **`src/server/ai/naturalLanguage/queryParser.ts`** — add optional `context?: ProjectAIContext` to `NLQueryInput`; add three intents matched *before* the generic find/fallback:
   - `summary` ("summarize/overview of my project", "project status")
   - `issues` ("what's wrong", "what are the issues", "is my project healthy")
   - `export_ready` ("can I export", "is it ready to export", "what's blocking export")
   Each renders a concise answer from `context` (no em dashes). When `context` is absent, behavior is unchanged.
4. **`src/server/ai/aiEngine.ts`** — thread optional `context` through `runNaturalLanguageQuery`.
5. **`src/server/routes/ai.ts`** — in `/ai/query` and `/ai/chat`, call `buildProjectAIContext(...)` and pass it into `runNaturalLanguageQuery`.
6. **`src/client/components/ChatPanel.tsx`** — add quick-query chips ("Summarize my project", "What's blocking export?", "Is my project healthy?") and refresh welcome copy.
7. **`src/test/ai.test.ts`** — add unit cases calling `parseAndExecuteQuery` with a stub `context` for the 3 new intents (find/count/etc. unchanged).
8. **Docs** — update `feature-catalog.md` (assistant now context-aware), `current-state-baseline.md` (capability), add a `docs/log.md` entry; run `npm.cmd run docs:check`.
