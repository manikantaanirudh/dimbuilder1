## Feature 8: Cross-Dimension Relationship Mapping — Implementation Plan

### Context

Explored the codebase to understand cross-dimension connections:
- `DimensionRecord.inheritedDimension` already tracks inheritance (e.g., UD3 inherits from "Corporate UD3")
- `OneStreamPropertyDefinition.valueType` includes `'memberRef'` — properties that reference members in other dimensions
- Member properties can contain references to members in other dimensions (e.g., Entity has "DefaultCurrency" referencing a currency member)
- The spec requires: dimension map, where-used lookup, inheritance chain visualization, and configurable cross-dimension validation rules

---

### Implementation Steps

#### Step 1: Create `src/shared/crossDimensionTypes.ts`
- `CrossDimensionMappingType` = `'reference' | 'mirror' | 'lookup' | 'default_value'`
- `CrossDimensionRuleType` = `'member_exists' | 'property_maps' | 'hierarchy_mirrors'`
- `CrossDimensionRule` — rule definition (id, projectId, name, source/target dim types, ruleType, ruleConfig JSON, severity, isActive, createdBy, createdAt)
- `CrossDimensionMapping` — explicit mapping entry (id, projectId, source/target dim+member, mappingType, createdAt)
- `DimensionRelationshipMap` — graph structure: `{ nodes: DimensionNode[]; edges: DimensionEdge[] }` where nodes are dimension types and edges represent reference relationships
- `DimensionNode` = `{ dimensionType: string; memberCount: number; hasInheritance: boolean }`
- `DimensionEdge` = `{ source: string; target: string; edgeType: 'inheritance' | 'property_ref' | 'rule'; referenceCount: number }`
- `WhereUsedResult` = `{ memberKey: string; dimensionType: string; references: WhereUsedReference[] }` where reference = `{ dimensionType: string; memberKey: string; propertyName: string; context: string }`
- `InheritanceChain` = `{ dimensionType: string; dimensionName: string; inheritsFrom: string; depth: number }`
- `CrossDimValidationResult` = `{ rules: CrossDimRuleResult[]; totalViolations: number }` where result = `{ ruleId: string; ruleName: string; violations: CrossDimViolation[] }`
- `CrossDimViolation` = `{ sourceMemberKey: string; targetDimensionType: string; message: string }`

#### Step 2: Add schema tables to `src/server/db/schema.ts`
- `cross_dimension_rules` table (id, project_id, name, source_dimension_type, target_dimension_type, rule_type, rule_config_json, severity, is_active, created_by, created_at)
- `cross_dimension_mappings` table (id, project_id, source_dimension_type, source_member_key, target_dimension_type, target_member_key, mapping_type, created_at)
- Indexes on project_id

#### Step 3: Add repositories to `src/server/db/repositories.ts`
- `crossDimensionRules` repo: create, list, update, delete
- `crossDimensionMappings` repo: create, listByProject, listByMember, delete

#### Step 4: Create `src/server/crossDimension/crossDimensionEngine.ts`
The core engine with these functions:
- `buildDimensionMap(projectData)` → scans all dimensions, members, and properties to find inter-dimension references (inheritance, property memberRefs, shared member keys). Returns `DimensionRelationshipMap`.
- `whereUsed(memberKey, dimensionType, projectData)` → searches all dimensions' members for properties that reference the given memberKey. Returns `WhereUsedResult`.
- `buildInheritanceChains(dimensions)` → walks `inheritedDimension` links to build chains. Returns `InheritanceChain[]`.
- `validateCrossDimension(rules, projectData)` → evaluates each active rule against project data, returning violations:
  - `member_exists`: for each member in source dim, check that a corresponding member exists in target dim
  - `property_maps`: for each member in source dim, check that a property value maps to a valid member in target dim
  - `hierarchy_mirrors`: check that the hierarchy structure in source dim is mirrored in target dim

#### Step 5: Create `src/server/routes/crossDimension.ts`
Routes per spec:
- `GET /projects/:id/cross-dimension/map` → calls `buildDimensionMap`
- `GET /projects/:id/cross-dimension/where-used?memberKey=&dimensionType=` → calls `whereUsed`
- `GET /projects/:id/cross-dimension/inheritance` → calls `buildInheritanceChains`
- `POST /projects/:id/cross-dimension/validate` → calls `validateCrossDimension`
- `GET /projects/:id/cross-dimension/rules` → list rules
- `POST /projects/:id/cross-dimension/rules` → create rule
- `DELETE /projects/:id/cross-dimension/rules/:ruleId` → delete rule
- `PATCH /projects/:id/cross-dimension/rules/:ruleId` → update rule

#### Step 6: Register routes in `src/server/app.ts`

#### Step 7: Create `src/test/crossDimension.test.ts`
Pure engine tests + API integration tests:
- **Map building**: Detects inheritance edges, property reference edges, counts references
- **Where Used**: Finds member references across dimensions via property values
- **Inheritance chain**: Builds correct chain depth with multiple levels
- **Validation**: member_exists rule generates violations for missing members, property_maps validates references, hierarchy_mirrors detects structural differences
- **API tests**: CRUD for rules, map/where-used/inheritance endpoints return correct data
