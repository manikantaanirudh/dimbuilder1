## Feature 7: AI-Powered Metadata Intelligence — Implementation Plan

### Context

Explored the full codebase architecture:
- **Types** defined in `src/shared/*Types.ts`, imported by server engines and tests
- **DB schema** in `src/server/db/schema.ts` (single exported `schemaSql` template literal)
- **Repositories** in `src/server/db/repositories.ts` (single `createRepositories()` function, exports `Repositories` type)
- **Routes** registered in `src/server/app.ts` via `Router` factories
- **Engine logic** in dedicated modules (e.g., `src/server/impact/impactEngine.ts`)
- **Tests** use vitest, in-memory DB, full HTTP server setup with auth tokens
- **Config** via `AppConfig` interface + `defaultAppConfig`

Feature 7 requires: LLM provider abstraction, 5 suggestion engines (parent, duplicate, naming, hierarchy optimization, property), natural language query, conversation storage, and AI configuration — all without requiring a real AI API key (graceful degradation + deterministic local algorithms for duplicate/naming detection).

---

### Implementation Steps

#### Step 1: Create `src/shared/aiTypes.ts`
Define all AI feature types:
- `AIProvider` = `'openai' | 'anthropic' | 'azure' | 'local' | 'none'`
- `AISuggestionType` = `'parent' | 'duplicate' | 'naming' | 'hierarchy' | 'property'`
- `AISuggestionStatus` = `'pending' | 'accepted' | 'dismissed'`
- `AISuggestion` interface (id, projectId, dimensionId, type, targetMemberKey, suggestion JSON, confidence, status, actedBy, timestamps)
- `AIConversation` interface (id, projectId, userId, messages[], timestamps)
- `AIMessage` = `{ role: 'user' | 'assistant' | 'system'; content: string; timestamp: string }`
- `DuplicateGroup` = `{ members: string[]; similarity: number; method: string }`
- `ParentSuggestion` = `{ parentKey: string; confidence: number; reason: string }`
- `NamingAnomaly` = `{ memberKey: string; pattern: string; deviation: string; confidence: number }`
- `HierarchyOptimization` = `{ parentKey: string; action: string; affectedMembers: string[]; reason: string }`
- `NLQueryResult` = `{ answer: string; matchedMembers: string[]; query: string }`
- `AIConfig` interface (enabled, provider, model, apiKey, features toggles, thresholds)

#### Step 2: Add `ai` section to `AppConfig`
- Add `AIConfigSection` to `appConfigTypes.ts`
- Add defaults to `appConfigDefaults.ts` with `ai.enabled: true`, `provider: 'none'`, all features enabled, similarity threshold 0.85

#### Step 3: Create AI schema tables in `src/server/db/schema.ts`
Add tables at end of `schemaSql`:
- `ai_suggestions` (id, project_id, dimension_id, suggestion_type, target_member_key, suggestion_json, confidence, status, acted_by, created_at, updated_at)
- `ai_conversations` (id, project_id, user_id, messages_json, created_at, updated_at)
- Indexes on project_id, suggestion_type, status

#### Step 4: Add AI repositories in `src/server/db/repositories.ts`
Add `aiSuggestions` and `aiConversations` repository sections:
- `aiSuggestions.create()`, `.listByProject()`, `.updateStatus()`, `.deleteByProject()`
- `aiConversations.create()`, `.get()`, `.listByProject()`, `.appendMessage()`, `.delete()`

#### Step 5: Create `src/server/ai/llmClient.ts` — LLM Provider Abstraction
- Interface `LLMClient` with `complete(prompt, options)` and `embed(text)` methods
- Factory function `createLLMClient(config)` that returns appropriate client
- `NoneLLMClient` — returns structured fallback responses (no API calls)
- `OpenAILLMClient` / `AnthropicLLMClient` stubs that call external APIs when configured
- All clients implement graceful degradation (return fallback when API unavailable)

#### Step 6: Create `src/server/ai/suggestions/parentSuggestion.ts`
- Analyzes hierarchy structure to suggest parents for a given member
- Uses sibling naming patterns, hierarchy depth heuristics
- Returns top-3 candidates with confidence scores and reasons
- Works purely from local data (no LLM needed for basic suggestions)
- If LLM available, enhances with semantic analysis

#### Step 7: Create `src/server/ai/suggestions/duplicateDetection.ts`
- Implements Levenshtein distance for fuzzy string matching
- Soundex/phonetic matching for similar-sounding member names
- Configurable similarity threshold (default 0.85)
- Groups duplicates across all members in a project
- Returns `DuplicateGroup[]` with similarity scores

#### Step 8: Create `src/server/ai/suggestions/namingAnomaly.ts`
- Detects common naming patterns per dimension (prefix patterns, case conventions, separators)
- Flags members that deviate from established patterns
- Uses statistical analysis (>70% of members follow pattern = pattern is "established")
- Returns anomaly list with confidence and suggested fix

#### Step 9: Create `src/server/ai/suggestions/hierarchyOptimization.ts`
- Identifies parents with too many children (>15 leaf nodes → suggest grouping)
- Detects "Other" catch-all parents with heterogeneous children
- Detects deeply nested single-child chains (compression candidates)
- Suggests rebalancing actions

#### Step 10: Create `src/server/ai/suggestions/propertySuggestion.ts`
- Auto-categorizes Account Type based on member name patterns (Revenue, Expense, Asset, Liability, Equity)
- Suggests missing property values based on sibling analysis
- Detects inconsistent property values within peer groups

#### Step 11: Create `src/server/ai/naturalLanguage/queryParser.ts`
- Parses natural language questions into structured queries
- Supports patterns like: "Which entities are missing [property]?", "Show members under [parent]", "Find accounts with [pattern]"
- Uses keyword extraction + pattern matching (no LLM required for basic queries)
- When LLM available, delegates complex queries to LLM

#### Step 12: Create `src/server/ai/naturalLanguage/responseGenerator.ts`
- Formats query results into human-readable responses
- Includes member counts, lists, and summaries

#### Step 13: Create `src/server/ai/aiEngine.ts` — Main orchestrator
- `runAnalysis(projectId, scope, projectData, config)` → triggers all relevant suggestion engines
- `suggestParent(memberKey, dimensionType, projectData, config)` → delegates to parentSuggestion
- `detectDuplicates(projectData, threshold, config)` → delegates to duplicateDetection
- `detectNamingAnomalies(projectData, config)` → delegates to namingAnomaly
- `suggestOptimizations(projectData, config)` → delegates to hierarchyOptimization
- `suggestProperties(projectData, config)` → delegates to propertySuggestion
- `queryNaturalLanguage(question, projectData, config)` → delegates to queryParser

#### Step 14: Create `src/server/routes/ai.ts` — API routes
Implement all endpoints from the spec:
- `GET /api/projects/:id/ai/suggestions` — list suggestions with filters
- `POST /api/projects/:id/ai/analyze` — trigger full analysis
- `PATCH /api/ai/suggestions/:id` — accept/dismiss suggestion
- `POST /api/projects/:id/ai/suggest-parent` — single member parent suggestion
- `POST /api/projects/:id/ai/query` — natural language query
- `POST /api/projects/:id/ai/chat` — conversation-based chat
- `POST /api/projects/:id/ai/duplicates` — duplicate detection
- `GET /api/ai/config` — get AI configuration
- `PATCH /api/ai/config` — update AI configuration (admin only)

#### Step 15: Register routes in `src/server/app.ts`
- Import `createAIRouter`
- Mount at `app.use("/api", createAIRouter(repos, config))`

#### Step 16: Create `src/test/ai.test.ts` — Comprehensive tests
- **Pure engine tests** (no server): Test each suggestion engine with fixture data
  - Parent suggestion: correct top-3 for known hierarchy
  - Duplicate detection: finds "Revenue" vs "Revenuee", "CostOfSales" vs "Cost_Of_Sales"
  - Naming anomaly: detects "revenue" among "Revenue", "Expenses", "Assets" (case violation)
  - Hierarchy optimization: detects 20-child parent, suggests grouping
  - Property suggestion: suggests AccountType for "Revenue_Total"
  - Natural language: parses "Which entities are missing currency?" correctly
- **API integration tests** (full server + auth):
  - POST analyze → creates suggestions in DB
  - GET suggestions with type/status filters
  - PATCH suggestion status → accepted/dismissed
  - POST suggest-parent → returns candidates with confidence
  - POST duplicates → returns grouped results
  - POST query → returns matching members
  - POST chat → creates/appends conversation
  - GET/PATCH config → requires admin for PATCH
  - Graceful degradation when AI disabled
